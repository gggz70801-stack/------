# 图片 / 视频处理规范（给我和 AI 看的一份说明）

这份文档解释"素材为什么必须压缩""要压到多少""怎么压"。
程序化的规则写在项目根目录的 `AGENTS.md` 里——**每次新的对话，AI 都会先读那份文件**，
所以哪怕隔了很多轮，它也会自动按同样的标准处理你上传的图。

---

## 一句话原则

> **进项目之前先压；原始大文件永远留在项目外面。**

你看到的高清作品，不等于"原始大图的体积"。网页上真正需要的，是**匹配显示尺寸**的版本。

## 图片

### 压到多少

| 用途 | 宽度 | 单张体积 | 格式 |
| --- | --- | --- | --- |
| 作品列表封面 | ≤ 1600px | ≤ 500KB | WebP（质量 80） |
| 作品详情长图 | 750–1200px（按 1:1 显示） | ≤ 800KB / 段 | WebP |
| 人物照片 | ≤ 1200px | ≤ 400KB | WebP |

### 为什么差这么多

一张 5000px 宽的相机原图约 5–6MB；网页上通常只显示到 1200–1600px 宽，转成 WebP 后约 200–400KB。
**重量变成 1/15，肉眼几乎看不出区别。**

### 长图怎么办

电商详情页那种 750×8000 的长图，切成 2–4 段（每段 750×2000 左右）。
这样页面可以"滚到哪加载哪"，不会一次性下载 4MB。

### 怎么压

```bash
# 把原图放进 media-src/works/<作品名>/ ，文件名用 01-、02- 排顺序
pnpm media:image                       # 全部处理
pnpm media:image --only amazon-listing  # 只处理某个作品
pnpm media:image --only awards          # 只处理获奖证书（awards / portrait 也能当"分组名"用）
```

处理完会：
1. 输出网页版到 `src/assets/works/<作品名>/`（网站自动读取，**不用改代码**）；
2. 生成 `src/data/gallery.json`（记录每张图的宽高，避免加载时页面跳动）；
3. 打印"原图多大 → 现在多大"的对照表。

### 动图（GIF）怎么办

详情页里那种会动的片段（GIF）**不会丢动画**：脚本会自动识别多帧图，输出**动画 WebP**，
并把帧数记进尺寸清单。动图的体积预算是静态图的 3 倍（多帧分摊），单张仍远小于 1MB。

### 不同分组的去向

| 原图放在 | 压缩后放到 | 用在页面 |
| --- | --- | --- |
| `media-src/works/<作品名>/` | `src/assets/works/<作品名>/` | 作品列表封面 + 详情页画廊 |

## 章节背景（SectionPlate）

### 它是干什么的

页面往下滚，有几个区块（「关于我」「跨境电商项目」「其他项目」「个人优势」「联系我」）原来会连着
出现大片纯黑，
看起来"空"。章节背景板就是往这些地方铺一张**压过色、压过暗、模糊过**的画面当底纹——
它是**氛围**，不是**画面**。

### 素材从哪来

目前有两套来源，处理规则相同：

1. 「关于我 / 联系我」来自 **《使命召唤》幽灵壁纸视频**（Wallpaper Engine 创意工坊作品）；
2. 「跨境电商 / 其他项目 / 个人优势」来自 `media-src/bg/tactical/` 的公开授权战术照片，
   逐张来源与授权记录见 `docs/backdrop-sources.md`，网页版由 `pnpm media:backdrops` 生成。

幽灵视频路径：

```
D:/STEAM/steamapps/workshop/content/431960/3133797682/WeChat_20240107180029.mp4
1280×720 / 17.6s / 5.4MB
```

这条视频的**画面本身很帅，但几乎每一帧都压着水印和花哨大字**：
右下角滚动字幕「CALL OF DUTY OKFINE YANG MENG XIN」、左上角红色大字母、
中后段直接糊上「GHOSTS」和「TOO MUCH CHARACTERS CAN'T DISPLAY」，
中间还有一句中文字幕。所以**选帧的第一条标准不是"帅"，是"干净"**：

| 帧 | 内容 | 用没用 | 原因 |
| --- | --- | --- | --- |
| 0.29s | 两个骷髅面罩特写 | ✗ | 画面很帅，但三处文字压得太满，裁不干净 |
| 6.75s | 幽灵＋队友，冷蓝夜戏 | ✓ | 只有底部一条水印，裁掉即可 → 「关于我」 |
| 12.03s | 幽灵正面特写 | ✗ | 正中间一条中文字幕，档在脸上 |
| 15.55s | 幽灵在火红光里，纯黑底 | ✓ | 只有底部一条水印 → 「联系我」 |
| 16.7s 之后 | 火焰 + 大字幕 | ✗ | 花哨大字已经铺满，只能用当纯色 |

### 怎么从视频变成背景板（两步）

```bash
# 1) 抽帧：30 张铺满整条视频，挑画面用（没有 ffmpeg 时会借用本机 Chrome，不用装东西）
pnpm media:frames --file "D:/STEAM/steamapps/workshop/content/431960/3133797682/WeChat_20240107180029.mp4" \
  --count 30 --out .frames

# 2) 处理：裁掉水印 → 单色化 → 压暗 → 模糊 → 出 WebP
pnpm plates
```

`scripts/make-section-plates.mjs` 是**一次性脚本**（和日常的 `media:image` 不是一回事），
参数都写在这个文件顶部的 `PLATES` 数组里，改完重跑即可：

| 参数 | 作用 |
| --- | --- |
| `crop` | 裁切。**这一步就是"删减花哨文字"**——把水印和字幕裁到画面外 |
| `saturate` / `tint` | 保色程度 / 单色染色。冷色板留一点蓝，暖色板留一点橙 |
| `brightness` / `contrast` | 明暗与对比 |
| `blur` | 模糊。轮廓在、细节糊，人物不会跳出来抢字 |

| 输出 | 形态 | 体积 |
| --- | --- | --- |
| `src/assets/section-bg/about-ghost.webp` | 1280×552 冷蓝单色 | 7.4KB |
| `src/assets/section-bg/contact-ghost.webp` | 1160×475 暖橙单色 | 8KB |

这两块加起来 **15KB**——背景板就该是这个量级，大一点都说明做错了。

### 页面上怎么用

统一走 `src/components/SectionPlate.jsx`（一个铺满章节的 `<div>` + 一层扫描线）。
参数全部是 CSS 变量，写在调用方自己的 css 里，`section-plate.css` 顶部列了默认值：

| 变量 | 作用 |
| --- | --- |
| `--plate-opacity` | 透明度。**改成 0 就等于关掉整块背景**（最省事的开关） |
| `--plate-blur` | 模糊。这是"很猛但很虚弱"的关键 |
| `--plate-mask` | 羽化遮罩。决定"哪一块露出来、哪一块提前收干净"，不会出现贴上去的矩形边 |
| `--plate-focus` | 相当于 `object-position`，决定画面里哪一块对着遮罩亮处 |
| `--plate-scan-opacity` | 那层扫描线的浓度 |

目前首页用了五块：

| 位置 | 文件 | 浓度 | 承担的任务 |
| --- | --- | --- | --- |
| 首页「01 关于我」 | `about-ghost.webp` | `0.44` | 填右半边空当，和暖色板形成冷暖两组 |
| 首页「02 跨境电商项目」 | `tactical/field-op.webp` | `0.34` | 在标题右侧建立夜训场景，到卡片区提前收暗 |
| 首页「03 其他项目」 | `tactical/hangar.webp` | `0.29` | 延续同一系列，只露出右上环境，正文区保持干净 |
| 首页「04 个人优势」 | `tactical/cod-visor.webp` | `0.25` | 用夜视装备收住能力章节，到卡片区提前收暗 |
| 首页「联系我」 | `contact-ghost.webp` | `0.16` | 填右半块空当，火红色温和全站琥珀橙同色温 |

全站还叠了一层 `.page-atmosphere`：低饱和暖 / 冷柔光、极细噪点和 96px 网格。
它固定在所有内容下方，只负责让纯黑区域“有空气”，不会覆盖文字、图片或交互。
如果觉得偏亮或偏暗，统一改 `src/styles/global.css` 里的 `.page-atmosphere`，
不需要碰每个页面。

想彻底删掉某一块：删掉对应组件里的 `<SectionPlate … />` 那一行即可，
**没有任何其它代码依赖它**。

> 顺带一提：之前「关于我」用的是一张黑白化的赛博壁纸（`about-breach.png`）。

> 母版还留在 `media-src/bg/about-breach.png`，想回退随时可以重新压一次。
| `media-src/portrait/` | `public/portrait/portrait.webp` | 「关于我」的人像 |
| `media-src/awards/` | `src/assets/misc/awards/` | 「关于我」的获奖证书 |

## 视频

### 压到多少

| 用途 | 时长 | 分辨率 | 体积 |
| --- | --- | --- | --- |
| 首屏背景视频 | **8–15 秒**（循环播放） | 1920×1080 | **≤ 12MB** |

原片往往是几十秒、接近 100MB。背景视频只需要"最精彩的那几秒循环"，**不需要整段**。

### 怎么压

```bash
pnpm media:video --file "E:/素材盘/bo3.mp4" --start 2 --duration 10 --bitrate 9
```

- `--start 2` 从第 2 秒开始截
- `--duration 10` 取 10 秒
- `--bitrate 9` 码率 9Mbps（分辨率保持 1920×1080，只降码率，肉眼几乎无损）

输出：
- `public/media/hero-loop.mp4`（网页版视频）
- `public/media/hero-poster.jpg`（同帧静帧，用于"先出图、视频后台加载"）

有 ffmpeg 就用 ffmpeg；没有就用本机 Chrome 的编码器转，**不需要联网、不需要装东西**。

### 首屏加载顺序（已经实现）

1. 打开页面的瞬间：显示矢量海报（0 下载）
2. 接着：显示 156KB 的静帧图（几乎瞬间）
3. 浏览器空闲时：才开始加载 11MB 的视频，加载好自动播放

所以访客第一眼看到的是图，不是等视频转圈。

## 常见疑问

**Q：作品多会不会放不下？**
不会。假设 30 个作品、每个 15 张图，压缩后每张 300KB，库存约 135MB——这是"书架上的书"。
访客每次只下载他点开的那一个作品（约 3–5MB），不是 135MB。

**Q：服务器会不会因为我放太多图而变慢？**
不会，变慢的是"单个文件太大"。真正要守的是单文件预算。

**Q：原始大图放哪？**
放项目外面的素材盘（例如 `E:\作品集\ACEBEAM\`），或放进 `media-src/`（不参与构建、不进 git）。
**永远不要把几十上百 MB 的原片放进 `public/`**——构建产物会被一起撑大，还会拖慢工具处理速度。

**Q：PSD 源文件要不要一起放进项目？**
不要。PSD / PSB 动辄几百 MB 到 1.5GB，只留在素材盘；项目里只放导出好的图片。
